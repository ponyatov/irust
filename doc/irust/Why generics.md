# 2.1.2 Why generics?
## Зачем нужны дженерики?

В статически типизированных языках, таких как Rust, компилятору необходимо знать **тип всех сущностей** на этапе компиляции. Это фундаментальное отличие от динамически типизированных языков вроде Python или Ruby, где типы определяются во время выполнения программы.

Дженерики позволяют писать код, который работает с **любыми типами**, при этом разработчику не нужно заранее знать конкретные типы. Вместо этого мы делегируем компилятору задачу определения типов на основе контекста использования.

Основная мотивация использования дженериков — следование принципу **«Не повторяйся» ([[DRY|Don't Repeat Yourself]])**. Без дженериков нам пришлось бы писать практически идентичный код для каждого типа, отличающийся лишь сигнатурами типов.

Несмотря на очевидные преимущества, использование дженериков имеет свои недостатки:

1. **Снижение читаемости** — абстрактный код может быть сложнее для понимания
2. **Увеличение когнитивной нагрузки** — программисту приходится отслеживать дополнительные уровни абстракции
3. **Необходимость аннотаций типов** — иногда компилятору требуются явные подсказки для вывода типов

Ключ к эффективному использованию дженериков — нахождение **баланса** между:

- **Абстракцией** — уменьшение дублирования кода
- **Читаемостью** — сохранение понятности кода
- **Практичностью** — использование только там, где это действительно необходимо
    
В большинстве случаев дополнительные умственные усилия, требуемые для работы с дженериками, оправданы долгосрочными преимуществами: более поддерживаемым, безопасным и производительным кодом.

Дженерики в Rust — это не просто синтаксический сахар, а фундаментальный механизм, позволяющий создавать **выразительные и типобезопасные абстракции** без накладных расходов во время выполнения.
